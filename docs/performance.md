# 성능

## 0.2.0: 3D를 Web Worker에서 그림

0.1.0에서 남은 TBT는 대부분 첫 WebGL 컨텍스트를 만들 때(SwiftShader 초기화, 실측 0.4~0.9초)와 처음 그릴 때 프로그램 링크를 기다리는 시간이었습니다. SwiftShader에는 셰이더를 병렬로 컴파일하는 확장(`KHR_parallel_shader_compile`)이 없어 링크가 끝났는지 묻는 순간 그리는 스레드가 기다립니다.

0.2.0에서는 캔버스를 `transferControlToOffscreen()`으로 워커에 넘겨, three.js 묶음 해석부터 장면 생성·셰이더 컴파일·프레임마다 그리기까지 모두 메인 스레드 밖으로 옮겼습니다. 메인 스레드는 화면 글자와 조작, 바뀐 화면 상태 전달, 이름표 옮기기만 맡습니다.

- 모바일 TBT 2.9초 → 0.04초, 성능 67 → 96. 같은 기기에서 E2E 17개가 약 1분 → 21초
- 소개 화면이 끝난 직후처럼 새로 보이는 재질의 셰이더를 컴파일하는 동안에도 버튼·패널은 막히지 않음 (3D만 잠시 늦게 갱신)
- OffscreenCanvas나 모듈 워커를 쓸 수 없는 브라우저는 0.1.0처럼 메인 스레드에서 그림

## 0.1.0에서 개선한 것

| 변경                                                                                                   | 효과                                                                           |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 첫 화면을 빌드 때 HTML로 그려 두고(SSR 사전 렌더링) 브라우저에서 이어받음                              | 3D를 기다리지 않고 제목·설명·버튼이 바로 보임                                  |
| 3D 장면은 글꼴을 받고 두 프레임을 그린 뒤 유휴 시간에 생성                                             | FCP·LCP 3.2초 → 1.6초 안팎                                                     |
| `compileAsync`로 셰이더를 먼저 컴파일하고 끝난 장면만 그림, 구의 분할 수 축소(행성 48×24, 그 밖 28×14) | 첫 프레임의 긴 작업 감소                                                       |
| 숫자 서식기(`Intl.NumberFormat`)를 설정별로 한 번만 만들어 다시 씀                                     | 10초 동안 서식에 쓰던 메인 스레드 약 1.2초(4배 감속) 제거                      |
| 3D는 매 프레임 최신 상태를 읽고, 패널 글자는 0.2초마다만 갱신 (사건·조작은 바로)                       | 화면 글자 재계산이 초당 60번 → 5번, 상호 작용 지연 감소                        |
| 렌더러를 만든 직후 비등방성 필터 확장을 미리 조회                                                      | 첫 텍스처 업로드 때 셰이더 컴파일이 끝나기를 기다리던 2.7초짜리 동기 호출 제거 |
| 배포본에서 셰이더 오류 검사(`checkShaderErrors`) 끔                                                    | 첫 사용 때 `getProgramInfoLog` 동기 호출(약 0.25초) 제거                       |
| `ImageBitmapLoader`로 텍스처 해석을 메인 스레드 밖에서, 작은 화면은 1024px 지구 텍스처                 | 텍스처 해석 중 긴 작업 없음, 모바일 텍스처 전송량 감소                         |
| 서비스 워커: 해시가 붙은 코드와 텍스처는 캐시 먼저, 페이지는 네트워크 먼저                             | 다시 방문하면 코드·텍스처를 내려받지 않음                                      |

## CI

`pnpm lighthouse`(Lighthouse CI)를 GitHub Actions에서 실행합니다. 접근성 95점, 권장사항·SEO 90점, CLS 0.1을 넘지 못하면 실패하고, 성능 60점·LCP 2.5초·전송량 2.5MB는 경고로만 알립니다. 결과는 실패할 때 `lhci-report/`로 올립니다.

## 다시 재기

```bash
pnpm build
pnpm lighthouse                                                     # 모바일
pnpm exec lhci collect --config=lighthouserc.cjs --settings.preset=desktop  # 데스크톱
```
